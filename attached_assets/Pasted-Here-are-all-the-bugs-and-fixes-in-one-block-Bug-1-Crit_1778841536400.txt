Bug 1 — Critical: Thumbnail never generated for uploaded videos
Files: MediaController.php → upload(), media_files table, ImageUploader.jsx, PropertyDetail.jsx
When a video is uploaded, the backend detects $isVideo = true and skips watermarking — but also skips everything else. There is no FFmpeg call, no frame extraction, no thumbnail_url returned. The media_files table has no thumbnail_path column. On the frontend, ImageUploader.jsx and AgentDashboardPage.jsx show a generic grey Video icon for all videos. PropertyDetail.jsx uses a hidden <video preload="metadata"> with onLoadedMetadata seeking to 0.001s to capture a first frame — this forces the browser to download the moov atom (1–15 MB) on every page load just to show a placeholder.

Bug 2 — Critical: Browser downloads entire .mp4 as a full file on card/listing pages
Files: PropertyCard.jsx → getImageUrl(), Properties.jsx, PropertyController.php → format()
getImageUrl() in PropertyCard.jsx takes images[0] blindly and returns /storage/videos/uuid.mp4 as the src of an <img> tag. The browser tries to load it as an image, fails after downloading a large portion of the file, then shows the fallback. This fires on every property card rendered in any listing.
Fix in PropertyCard.jsx:
jsfunction isVideoPath(p) {
  return /\.(mp4|mov|avi|mkv|webm|m4v)(\?.*)?$/i.test(p || '')
}

function getImageUrl(property) {
  if (property?.thumbnail_url) return property.thumbnail_url
  const images = Array.isArray(property?.images) ? property.images : []
  const firstImage = images.find(img => !isVideoPath(img))
  const img = firstImage || property?.image
  if (!img || isVideoPath(img)) return FALLBACK
  return img.startsWith('http') ? img : `/storage/${img}`
}
Fix in PropertyController.php → format():
php'thumbnail_url' => $this->extractThumbnail($images),

private function extractThumbnail(array $images): ?string {
    foreach ($images as $img) {
        if (!preg_match('/\.(mp4|mov|avi|mkv|webm|m4v)$/i', $img)) {
            return str_starts_with($img, 'http')
                ? $img
                : Storage::disk('public')->url($img);
        }
    }
    return null;
}

Bug 3 — Performance: preload="metadata" on hidden video forces partial MP4 download
Files: PropertyDetail.jsx:253–256, ProjectDetail.jsx:150
The play-button overlay is built by rendering a hidden <video preload="metadata"> and seeking to 0.001s on onLoadedMetadata to grab a first-frame thumbnail. This forces the browser to fetch the moov atom (can be megabytes at the start of an MP4) on every property detail page load — even when the user never clicks play. Covered by Bug 1 fix above: replace with poster={property.thumbnail_url || ''} and preload="none".

Bug 6 — Conflict: Video path stored as raw path but only some components know to stream it
Files: MediaController.php, ImageUploader.jsx, PropertyDetail.jsx, PropertyCard.jsx
The backend stores path: "videos/uuid.mp4" and ImageUploader.jsx pushes this raw path into the property's images[] array. PropertyDetail.jsx has a local mediaUrl() function that correctly converts it to /api/v1/stream/videos/uuid.mp4. But PropertyCard.jsx, Properties.jsx, and the thumbnail strip all use /storage/{path} directly — so the video path reaches an <img src="/storage/videos/uuid.mp4"> and produces a broken image plus wasted bandwidth.
Fix — create one shared utility used everywhere:
js// src/utils/media.js
export const VIDEO_EXTS = ['mp4','mov','avi','mkv','webm','m4v']

export function isVideoPath(p = '') {
  const ext = p.split('?')[0].split('.').pop().toLowerCase()
  return VIDEO_EXTS.includes(ext)
}

export function mediaUrl(path) {
  if (!path) return ''
  if (path.startsWith('http') || path.startsWith('blob:')) return path
  if (isVideoPath(path)) return `/api/v1/stream/${path}`
  return `/storage/${path}`
}
Then remove the duplicated isVideoPath and mediaUrl/imgUrl definitions from PropertyDetail.jsx, ProjectDetail.jsx, ImageUploader.jsx, and AgentDashboardPage.jsx and import from this file instead.
