Root Cause Analysis
The error "FFmpeg could not extract a frame from this video." comes from rethumbnail() in MediaController.php — all 5 FFmpeg strategies in generateVideoThumbnail() fail and return null. There are several possible causes:
1. FFmpeg is not installed / not found by PHP
The most common cause. PHP's web process often has a restricted PATH that doesn't include where FFmpeg lives. Your getFfmpegBin() method tries which ffmpeg but that may return nothing when run by the web server user (www-data).
Fix — hardcode a known path or log it properly:
phpprivate function getFfmpegBin(): string
{
    // Add this to confirm what path PHP can actually see:
    \Illuminate\Support\Facades\Log::debug('FFmpeg search PATH', ['PATH' => getenv('PATH')]);

    $bin = trim((string) @shell_exec('which ffmpeg 2>/dev/null'));
    if ($bin && file_exists($bin)) return $bin;
    // ... rest of the method
}
Run which ffmpeg as your web server user to find the real path, then hardcode it in $candidates[].

2. exec() is disabled in PHP config
generateVideoThumbnail() checks disable_functions for exec, but shell_exec (used in getFfmpegBin()) might also be disabled separately.
Check: In a test route or tinker, run:
phpdd(ini_get('disable_functions'));
dd(shell_exec('which ffmpeg'));
dd(exec('ffmpeg -version'));

3. The video file has a codec FFmpeg can't decode without extra libraries
Some .mov or .mkv files use codecs (HEVC/H.265, AV1, VP9) that may not be compiled into your FFmpeg build.
Fix — add this fallback strategy to $strategies[] in generateVideoThumbnail():
php// Strategy 6: Use thumbnail filter (picks best frame) instead of -frames:v 1
$base . $in_arg . ' -vf "thumbnail,scale=640:-2" -frames:v 1 ' . escapeshellarg($thumbDiskPath),
// Strategy 7: Force scale2ref, no seek, raw output
$base . ' -skip_frame noref' . $in_arg . ' -frames:v 1 -vf scale=640:-2 -q:v 5 ' . escapeshellarg($thumbDiskPath),

4. The rethumbnail path uses the wrong local disk path for cloud-stored videos
If videos are stored on S3/cloud (not local disk), Storage::disk('public')->path($record->path) returns a local path that doesn't exist. The code does try to download it via file_get_contents($remoteUrl) as a fallback, but this can fail if the URL requires auth or has CORS restrictions.
Check: Add a log before the thumbnail generation:
php\Log::info('rethumbnail attempt', [
    'videoFullPath' => $videoFullPath,
    'exists' => file_exists($videoFullPath),
    'size' => file_exists($videoFullPath) ? filesize($videoFullPath) : 0,
]);

5. The thumbs/ directory can't be written to
The @mkdir() silently fails if permissions are wrong.
Add explicit check:
php$thumbDir = dirname($thumbDiskPath);
if (!is_dir($thumbDir) && !mkdir($thumbDir, 0755, true)) {
    \Log::error('Cannot create thumbs directory', ['dir' => $thumbDir]);
    return null;
}
