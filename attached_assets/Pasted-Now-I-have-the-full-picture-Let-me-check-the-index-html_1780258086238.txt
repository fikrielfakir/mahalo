Root Cause: Two Separate Problems
Problem 1 — Backend saves the file to the wrong path
In AdminSettingsController::uploadOgImage():

php
$frontendPublic = base_path('frontend/public');
$file->move($frontendPublic, 'og-image.png');
base_path('frontend/public') resolves to something like /var/www/html/frontend/public — not your web-server's public_html. So the file is uploaded to a directory that the web server never serves, while the old static public_html/og-image.png remains untouched.

Fix: Save directly into public_html (your document root):

php
// Point at the actual web-served public_html directory
$publicHtml = public_path();          // resolves to public_html/
$file->move($publicHtml, 'og-image.png');
public_path() is the correct Laravel helper — it resolves to the public/ folder that is symlinked or served as public_html on your host.

Problem 2 — index.html has the OG image hardcoded
The dynamic og_image_url from the DB is read by SEOHead.jsx and injected at runtime by React-Helmet. But crawlers (Facebook, Twitter, Google, WhatsApp) do not execute JavaScript — they read the raw HTML. So they always see:

html
<meta property="og:image" content="https://mahalo.ma/og-image.png" />
This static fallback in index.html overrides everything for bots, regardless of what the admin uploads.
